# Legacy audit 61,501–73,800

Source: `legacy/app/src/main/assets/index.html`. Range covers the RPC-manager drawer, home portfolio/delegation badges, the SUP Transfer Bot v2 (ERC-4337 batch UserOps), the whole Transfer Hub (TH) multi-RPC engine, inline transfer-contract deployment, the Withdraw Manager, Phrase→Key, Self Transfer, Multi-Key native/token flows, NFT distribute/collect and the W2W (wallet-to-wallet) helpers. No framework: string-template DOM + IIFEs on `window`.

## 61,501–63,300 — RPC drawer, home cards, SUP bot

RPC manager drawer: `rpcDrawerShowDetail` 61552, `_rpcRenderList` 61580, `rpcAddNew` 61668, `rpcSetDefault` 61700 (flushes RPC cache and re-syncs every TH hidden `rpcUrl*` input), `rpcRemoveCustom` 61803. Home: chain-tile long-press patch, `_homePortfolioCardSync` (greeting text, `MutationObserver` + 2 s poll), `_nexusUsdToggleAndSilentRefresh` (15 s silent price refresh, 3 s USD/currency toggle), `_nexusDelegatedStatClick` / `profileDelegatedCardClick` — batched `eth_getCode` EIP-7702 probe (`0xef0100` prefix), `BATCH_SIZE 20`, `TIMEOUT 7000`, 2 retries, concurrency 4.

SUP Transfer Bot v2 (≈62,1xx–63,300): `supRunBatch` 62852 assembles one ERC-4337 `UserOp` per sender, packs it locally, sends via HTTP bundler, waits receipts. Constants: EntryPoint `0x5FF137D4b0FDCD49DcA30c7CF57E578a026d2789` 62311, dummy 65-byte signature, `BUNDLER_MIN 7660000n` 62871, `MAX_SEND_MS 60000` 62985, send back-off `Math.min(3000 + attempt*500, 10000)` 63000, 40 × 3 s receipt polls 63046. Encrypted wallet blobs are persisted to `nexus_sup_pks` after `NexusCrypto.encrypt` (62508). Sponsored gas on Base 8453 via paymaster stub/data (`pm_getPaymasterStubData`, `pm_getPaymasterData`), then `eth_sendUserOperation`, `eth_getUserOperationReceipt`; tx links are hard-coded `https://basescan.org` regardless of chain.

Sponsorship: `thSendWithSponsor` 64861 / `thTokenSendWithSponsor` 64884 — when `chainId === 8453 && typeof sendSwapViaUserOp === 'function'` (64863) the tx is routed through the Coinbase paymaster path, else plain `wallet.sendTransaction(txReq)` (64880). Background hardening 64950+ overrides `document.hidden`/`visibilityState` while a tx runs, plus silent WebAudio oscillator and 100 ms keep-alive. `_thSaveTx` 65037 (history bridge), `createExplorerLink` 65059, `copyToClipboard` 65130 → `window.NexusAndroid.copyToClipboard(text)` when `window.isNexusAndroid`.

## Quirks / bugs seen

- 61671–61673: error says "must start with https://" while the check accepts `http`.
- 73528: `savedContractsMultiKeyNative.forEach` is unguarded; 739xx onward reuses `sanitisePrivateKey`/`resolveRecipientAddress` defined outside this range.
- 73706–73713: computes `_thRpcs`/`_thChainId` then never uses them; direct-transfer mode reads token-section fields (`tokenContractAddressMultiKeyToken`, `tokenSymbolMultiKeyToken`) and ignores the recipients list entirely (single recipient only).
- 73647: recipient regex `/^0x[a-f0-9]{40}/i` lacks `$` — trailing garbage passes.
- 73442/73445 log "ETH" even on non-ETH chains; SUP links always basescan.
- Empty `catch` blocks hide balance/parse errors (72604, 72885+).

## Security notes (values masked)

- 62508: `nexus_sup_pks` is the only encrypted store here (`NexusCrypto.encrypt`); plaintext keys live in the in-memory `window.actualKeysStorage` and in textareas (73115–73116).
- 69614/69730: Phrase→Key renders raw private keys in the DOM with a copy affordance.
- 68429/68576: developer private keys for withdraw contracts are typed into `withdrawDeveloperKey` and used for client-side signing.
- 73735: keys are re-sanitised but never zeroed after use; no API key literals are introduced in 72,301–73,800 (only public RPC/explorer hosts and the public EntryPoint address).
