# Legacy audit 73,801–86,100

File: `legacy/app/src/main/assets/index.html` (read-only). Range covers the tail of the multi-key transfer tools, balance/approval utilities, the wallet-to-wallet (W2W) and NFT tools, background-keepalive/PWA/Capacitor shims, the full Web3 (EIP-1193) bridge used by the in-app browser, and the start of the Exchange engine config. Single inline `<script>` blocks; no build step.

## Security findings

- Alchemy API key is embedded in the user-supplied RPC URL and reused verbatim for NFT calls (80,131–80,134); treat as `abc…`.
- Coinbase Paymaster endpoint read from `nexus_paymaster_url` / `nexus_bsb_pm` (16,260); never printed in this range.
- Private keys live in `window.actualKeysStorage` in memory and are deliberately shown unmasked in key inputs; masking disabled.
- Storage guard blocks only bare 64-hex/mnemonic strings — JSON or base64 wrapped keys pass (78,069–78,114).
- `allowMixedContent: true` in the Capacitor config comment block (83,318+) allows HTTP subresources.
- `eth_sign` implemented without the usual "blind signing" interstitial; typed-data and tx sheets share one approval modal.

## Quirks worth reproducing

- `NexusBGGuard` ref-counting means a thrown error between `txStart`/`txEnd` keeps the wake lock + audio alive indefinitely.
- Approval manager's missing `txEnd` on success (77,067).
- `w2wReceivers` vs `w2wReceiverKeys` id mismatch (78,703/78,726).
- Undefined `logMessageMultiToken` (81,043) and undeclared `rpcUrl` (74,447).
- 500k-block `eth_getLogs` + per-token `ownerOf` scanning as NFT fallback (80,366–80,560) — slow and rate-limit prone.
