## Security findings (values masked)

- Hardcoded **LiFi** key `x-lifi-api-key: b3e…` at 49470, 49702, 49873, 50092, 50655, 56264, 59328.
- Hardcoded **Odos** `x-api-key: 7d2…` 56326, 56337.
- **1inch** `Authorization: Bearer` + `_API_KEYS.INCH_API` 56376 (value defined outside range).
- **Enso** `Authorization: Bearer 2fd…` 56832; **DODO** `apikey: 317…` 56883; **Squid** `x-integrator-id: nexus-wallet-8a0…` 57055.
- **OKX** full credential set in client JS: `OKX_KEY 4ea…`, `OKX_SECRET CB2…`, `OKX_PASSPHRASE ak0…` at 56958–56960 and duplicated at 59469–59471; HMAC-SHA256 signed in-page with `crypto.subtle` (59474–59489), headers `OK-ACCESS-KEY/SIGN/TIMESTAMP/PASSPHRASE`.
- **Rango** key in query string (`window._NEXUS_RANGO_KEY`) 50051, 56695, 59411.
- Private keys exist in plaintext in JS memory (`SW.walletPK`, `validatedKeys`, wallet groups); only `nexus_sw_signer` is AES-encrypted (`NexusCrypto`, legacy `pk` auto-migrated).
- App Lock: the AES master secret is stored **in plaintext** in localStorage (`nexus_lock_master_secret`) — anyone with WebView storage access can decrypt all wallets; the 6-digit PIN hash is salted SHA-256 (offline brute-force ≈10^6 tries); pattern hash is unsalted SHA-256 of a 3–9 dot path; biometric unlock accepts a boolean callback from the native bridge with no crypto binding.
- Swap safety relies on substring search for the wallet address inside calldata, explicitly bypassed for OKX.
